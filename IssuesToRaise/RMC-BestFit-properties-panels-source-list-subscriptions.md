# Properties panels' source lists: five never let go of the project when closed before loading, and eight stop following it after an unload

**Target:** [USACE-RMC/RMC-BestFit](https://github.com/USACE-RMC/RMC-BestFit), `src/RMC.BestFit.App/GUI`: the properties panels of Input Data, Fitting Analysis, Univariate, Bulletin 17C, Mixture, Point Process, Bivariate and Rating Curve analyses (`ElementCallback`, `UserControl_Unloaded` and their `Load…` methods). Found in 2.0.1 at commit [`bfce2dd`](https://github.com/USACE-RMC/RMC-BestFit/tree/bfce2ddbebb8d75e6cf6e21c4fef8ecfb5058269), still `main` on 2026-10-31.

**Type:** bug (memory leak; stale list) · **Severity:** low

**Verification:** verified by reading the source. The second problem was also seen in XGoodFit's port of the Rating Curve panel, which keeps upstream's code: a test unloads and reloads the panel, adds a time series to the project, and finds it missing from the panel's list ([`RatingCurveAnalysisViewTests.cs` lines 414-423](https://github.com/jonklaric/XGoodFit/blob/149b96b320911b89c8b64cc786b3a4d1828896e6/tests/BestFit/RMC.BestFit.App.Tests/XGoodFit/RatingCurveAnalysisViewTests.cs#L414-L423)).

Related: [Closed document views stay subscribed to their elements](RMC-BestFit-views-not-released-after-close-or-replace.md), the same kind of leak in the document views.

## Summary

Each of these panels lists the project's elements of one kind for its source combo boxes (time series, input data or univariate analyses), and keeps the list current by subscribing to that collection's `ElementAdded` and `ElementRemoved`. It subscribes when its `Element` is set, and unsubscribes when it unloads. Two things go wrong:

1. **Five panels never unsubscribe when their `Element` is cleared.** The shell closes a properties panel by setting `Element = null`, and their `ElementCallback` returns on a null element before it unsubscribes. That's harmless for a panel that was shown, since its `Unloaded` handler unsubscribes. But WPF raises `Unloaded` only for a control that was loaded, so a panel that is replaced or closed before it loads stays subscribed to a collection that lives as long as the project. RMC-BestFit's project is a singleton, so that's the application's lifetime, and the panel's list keeps growing as elements are added.
2. **Eight panels never subscribe again after an unload.** They unsubscribe in `Unloaded` and subscribe only when `Element` is set, so a panel that unloads and loads again, as a docked panel does when AvalonDock re-templates it for a theme change, no longer follows the project. Elements added later are missing from its combo boxes, and deleted ones stay listed, until another element is selected.

Three panels get both right: Time Series Analysis, Composite and Coincident Frequency unsubscribe before the null check and subscribe again on `Loaded`, reconciling the list.

## Details and how to reproduce

The second problem, in the Rating Curve panel:

1. Select a rating curve analysis, so its properties show.
2. Change the theme (**Tools > Options...**), which re-templates the docked panel; upstream's own `AnalysisSourceSelectionLifecycleTests` says "The actual AvalonDock template replacement must unload the panel."
3. Import a new time series.
4. Expected: it's listed under **Stage Data** and **Discharge Data**. Actual, by reading and in XGoodFit's port: it isn't, until another element is selected and this one again.

The first: a panel that never loads. `MainWindow.OpenProperties` calls `PropertiesClosed` on the previous panel, setting its `Element` to null, whatever its state. A panel replaced before WPF raises its `Loaded` event (for example by a second selection, or a plot's properties request, in the same dispatcher turn), or probably one placed in the Properties pane while the pane is closed or auto-hidden, keeps its handlers. A memory profiler, or a `WeakReference` to such a panel after a forced collection, would show it.

## Why this is an issue and not intended behaviour

- The panels' own comments say the unsubscriptions are there "to prevent memory leaks", and `PropertiesClosed` sets `Element = null` "allowing proper cleanup". For five panels, clearing `Element` doesn't clean up, and `Unloaded` can't stand in for a panel that never loaded. Fitting Analysis, Mixture and Point Process show the intended order: unsubscribe, then return on null.
- For the second problem, upstream already fixed three panels the same way and tests them: `AnalysisSourceSelectionLifecycleTests` runs its "Unloaded collection changes" case for the Time Series Analysis, Composite and Coincident Frequency panels only. The Time Series Analysis panel's `LoadTimeSeries` even notes why a reload must reconcile rather than clear: "A Reset removes the selected item and writes null through the two-way binding."

## Suggested fix

Do what the Time Series Analysis panel does, in the other eight:

1. In `ElementCallback`, unsubscribe from the collection before the null check.
2. Handle `Loaded`: if `Element` is set, subscribe again and reconcile the list with the collection (remove what's gone, add what's new), rather than clearing it. Clearing writes null through the combo boxes' two-way bindings and would change the element's source.

Then extend `AnalysisSourceSelectionLifecycleTests`' "Unloaded collection changes" case to these panels. No compatibility risk.
