# Cleanup: unused code, styles that never apply, and resource references that resolve to nothing

**Target:** [USACE-RMC/WPF-Framework](https://github.com/USACE-RMC/WPF-Framework): GenericControls, NumericControls, DatabaseControls, FrameworkUI and OxyPlotControls. Found in 1.0.5 at commit [`7f897e1`](https://github.com/USACE-RMC/WPF-Framework/tree/7f897e107db4a25cca29127ce9d564898c5fde93), still `main` on 2026-10-30.

**Type:** bug (cleanup) · **Severity:** low

**Verification:** each item verified by reading the source and searching the whole of WPF-Framework and RMC-BestFit for references.

## Summary

Small things found while porting the framework to Avalonia. None changes a result or a file, and two are visible: a dialog without an icon, and a slightly different text colour in one theme. They're grouped as one checklist so they can be fixed together.

## Details and how to reproduce

Each item below says what to look for. Most can be confirmed by searching the repository for the name it gives: the search finds the definition and no use.

## Why this is an issue and not intended behaviour

Each item goes against the code's own intent: a style written to apply that can't, a resource key that resolves to nothing, a handler or helper with no caller, or a file whose entries don't follow its own note. Together they add binding errors, a missing icon and dead weight, and they make it harder to see what the framework really uses.

## Where in the source

Links are permalinks at `7f897e1`, relative to `src/`.

**Styles and resources that never apply or resolve**

1. **Implicit `NameDialog` and `MessageBoxWindow` styles never apply.** [`GenericControls/Themes/GenericControlsTheme.xaml` lines 266-282](https://github.com/USACE-RMC/WPF-Framework/blob/7f897e107db4a25cca29127ce9d564898c5fde93/src/GenericControls/Themes/GenericControlsTheme.xaml#L266-L282) defines them, but both windows set `Style="{DynamicResource MetroDialogStyle}"` locally ([`NameDialog.xaml` line 10](https://github.com/USACE-RMC/WPF-Framework/blob/7f897e107db4a25cca29127ce9d564898c5fde93/src/GenericControls/Windows/NameDialog.xaml#L10), [`MessageBoxWindow.xaml` line 9](https://github.com/USACE-RMC/WPF-Framework/blob/7f897e107db4a25cca29127ce9d564898c5fde93/src/GenericControls/Windows/MessageBoxWindow.xaml#L9)), and a local `Style` replaces an implicit one. `MetroDialogStyle` uses `MainWindowCaptionActive*` instead of `EnvironmentWindow*`. The two backgrounds are equal in every palette; the text differs only in Blue (#1B293E against #000000). Delete the two styles, or base them on `MetroDialogStyle` and drop the local `Style`.
2. **FrameworkUI's `PDF` image points to a file that isn't in the project.** [`FrameworkUI/Icons/IconDictionary.xaml` line 17](https://github.com/USACE-RMC/WPF-Framework/blob/7f897e107db4a25cca29127ce9d564898c5fde93/src/FrameworkUI/Icons/IconDictionary.xaml#L17): `/FrameworkUI;component/Resources/PDF.png`. `Resources/` holds only `AvalonDock.xml`, `CompressProject.png` and `USACE.png`. Nothing references the key yet; the first lookup would throw. Remove the entry or add the image.
3. **The Recent Files dialog's icon key is undefined.** [`FrameworkUI/Recent Files/RecentFilesDialog.xaml` line 9](https://github.com/USACE-RMC/WPF-Framework/blob/7f897e107db4a25cca29127ce9d564898c5fde93/src/FrameworkUI/Recent%20Files/RecentFilesDialog.xaml#L9): `Icon="{DynamicResource RecentProjects}"`. No `RecentProjects` resource exists, so the dialog has no icon. The other dialogs use `DrawingImage` keys (`SaveImage`, `OptionsImage`); the closest match, `RecentProjectIcon` (line 150 of the icon dictionary), is a `Viewbox` menu icon and can't be a window icon. Add a `RecentProjectsImage` `DrawingImage` and use it.
4. **Three icons aren't `x:Shared="False"` although the dictionary says all are.** [`GenericControls/Resources/IconDictionary.xaml` line 35](https://github.com/USACE-RMC/WPF-Framework/blob/7f897e107db4a25cca29127ce9d564898c5fde93/src/GenericControls/Resources/IconDictionary.xaml#L35) says "All icons use x:Shared="False" to allow multiple instances", but `SortAscFilterIcon`, `SortDescFilterIcon` and `ClearFilterIcon` ([lines 329, 349, 369](https://github.com/USACE-RMC/WPF-Framework/blob/7f897e107db4a25cca29127ce9d564898c5fde93/src/GenericControls/Resources/IconDictionary.xaml#L329-L369)) don't set it. They also re-declare the default `xmlns`. They're used as menu icons in `TableViewer` and `CopyPasteDataGrid`: one shared element moves between menus, so two open menus can't both show it.

**Unused or unreachable code**

5. **`BooleanToBrushConverter.ConvertBack` can never match.** [`GenericControls/Utilities/Converters.cs` lines 208-219](https://github.com/USACE-RMC/WPF-Framework/blob/7f897e107db4a25cca29127ce9d564898c5fde93/src/GenericControls/Utilities/Converters.cs#L208-L219) tests `value.GetType() == typeof(Brush)`. `Brush` is abstract, so no value's type is `Brush`, and the method always returns `null`. Use `value is Brush`. The converter is public but unused in WPF-Framework and RMC-BestFit.
6. **`StringListPropertyControl`'s callback has an `// Exit Sub` without a `return`.** [`GenericControls/Properties Controls/StringListPropertyControl.xaml.cs` line 96](https://github.com/USACE-RMC/WPF-Framework/blob/7f897e107db4a25cca29127ce9d564898c5fde93/src/GenericControls/Properties%20Controls/StringListPropertyControl.xaml.cs#L96): `if (e.NewValue == null) thisControl.StringList = new List<string>(); // Exit Sub`. Assigning re-enters the callback, which builds the grid, and then the outer call builds it again. Add `return;`. There's no visible effect.
7. **The "italic for NaN" converter is declared but never used, and is misnamed.** [`NumericControls/Data/Time Series Editor/TimeSeriesTable.xaml` line 110](https://github.com/USACE-RMC/WPF-Framework/blob/7f897e107db4a25cca29127ce9d564898c5fde93/src/NumericControls/Data/Time%20Series%20Editor/TimeSeriesTable.xaml#L110) declares `DoubleToItalicsConverter`, but no binding uses it, so NaN and infinite values are never italic. The class, `DoubleToFontFamilyConverter` ([`TimeSeriesTable.xaml.cs` lines 818-831](https://github.com/USACE-RMC/WPF-Framework/blob/7f897e107db4a25cca29127ce9d564898c5fde93/src/NumericControls/Data/Time%20Series%20Editor/TimeSeriesTable.xaml.cs#L818-L831)), returns a `FontStyle`. Either bind the value column's `FontStyle` to it or remove both.
8. **The uncertain table's merged header binds to elements that don't exist.** [`NumericControls/Data/Uncertain Curve Editor/UncertainOrderedTableEditor.xaml` lines 42-44](https://github.com/USACE-RMC/WPF-Framework/blob/7f897e107db4a25cca29127ce9d564898c5fde93/src/NumericControls/Data/Uncertain%20Curve%20Editor/UncertainOrderedTableEditor.xaml#L42-L44): `ElementName=Column1` and `Column2`. These bindings fail at load (binding errors in the output window). `ValidationGrid_AutoGeneratedColumns` replaces the definitions with working ones ([`UncertainOrderedTableEditor.xaml.cs` lines 500-526](https://github.com/USACE-RMC/WPF-Framework/blob/7f897e107db4a25cca29127ce9d564898c5fde93/src/NumericControls/Data/Uncertain%20Curve%20Editor/UncertainOrderedTableEditor.xaml.cs#L500-L526)), so only the errors remain. Leave the XAML definitions without bindings.
9. **FrameworkUI's `UtilityFunctions` has three unused helpers that reflect on WPF internals.** `Clone(this MenuItem)`, `CopyClick` and `GetRoutedEventHandlers` ([`FrameworkUI/Utilities/UtilityFunctions.cs` lines 229-340](https://github.com/USACE-RMC/WPF-Framework/blob/7f897e107db4a25cca29127ce9d564898c5fde93/src/FrameworkUI/Utilities/UtilityFunctions.cs#L229-L340)) have no callers. `GetRoutedEventHandlers` reads the internal `UIElement.EventHandlersStore` by reflection (lines 321-330), which can break with any .NET update. Remove them.
10. **`OptionsDialog_Closing` is never attached.** [`FrameworkUI/Tools Menu/Options/OptionsDialog.xaml.cs` lines 187-194](https://github.com/USACE-RMC/WPF-Framework/blob/7f897e107db4a25cca29127ce9d564898c5fde93/src/FrameworkUI/Tools%20Menu/Options/OptionsDialog.xaml.cs#L187-L194) ("On closing, activate the Main Window"), but neither the XAML nor the code subscribes it. WPF re-activates a modal dialog's owner anyway, so wire it up or delete it.
11. **`GenericSeriesControl`'s `PlotChanged` mechanism is dead.** [`OxyPlotControls/Series/GenericSeriesControl.xaml.cs`](https://github.com/USACE-RMC/WPF-Framework/blob/7f897e107db4a25cca29127ce9d564898c5fde93/src/OxyPlotControls/Series/GenericSeriesControl.xaml.cs#L37): the `PlotChanged` event (line 37) has no subscribers, and `OnBindingSourceUpdated` (lines 315-318), its only caller of `OnPlotChanged`, is never attached to `Binding.SourceUpdated`.
12. **The DatabaseControls demo's `ExportMenuItem_Click` is unreachable.** [`DatabaseControls.Demo/MainWindow.xaml.cs` line 176](https://github.com/USACE-RMC/WPF-Framework/blob/7f897e107db4a25cca29127ce9d564898c5fde93/src/DatabaseControls.Demo/MainWindow.xaml.cs#L176): no menu item in `MainWindow.xaml` uses it (the only handler wired there is `SelectDatabaseButton_Click`). Add the menu item or remove the handler.

**Unused resources compiled into an assembly**

13. **35 images in DatabaseControls, 29 referenced nowhere.** `DatabaseControls.csproj` compiles every `Resources\*.png` and `*.ico` as a WPF resource ([lines 33-34](https://github.com/USACE-RMC/WPF-Framework/blob/7f897e107db4a25cca29127ce9d564898c5fde93/src/DatabaseControls/DatabaseControls.csproj#L33-L34)). Of the 35, 29 aren't referenced anywhere in WPF-Framework or RMC-BestFit (for example `Calculator.ico`, `EditOn.png`, `Undo.ico`, `Redo.png`, `Save.ico`, `UpArrow.png`). The other 6 (`Plus.png`, `Minus.png`, `Mult.png`, `Divide.png`, `Exponent.png`, `Equals.png`) are referenced only inside an XML comment in [`FieldCalculator/SelectByAttribute.xaml` lines 44-59](https://github.com/USACE-RMC/WPF-Framework/blob/7f897e107db4a25cca29127ce9d564898c5fde93/src/DatabaseControls/FieldCalculator/SelectByAttribute.xaml#L44-L59). Removing them shrinks the assembly.

## Suggested fix

As noted per item. None touches a file format or a public behaviour beyond the two visible items (3 and 1).

## How XGoodFit handles it

XGoodFit (a port of RMC-BestFit to Avalonia) keeps these as upstream has them, except that it doesn't port the 35 unused images ([`DatabaseControls.csproj` header](https://github.com/jonklaric/XGoodFit/blob/fcb3902c2937662ed5f1b3869e0ea019e88e3c63/src/Framework/DatabaseControls/DatabaseControls.csproj)). Items 1, 5 and 6 are noted in [`GenericControlsTheme.axaml`](https://github.com/jonklaric/XGoodFit/blob/fcb3902c2937662ed5f1b3869e0ea019e88e3c63/src/Framework/GenericControls/Themes/GenericControlsTheme.axaml), [`Converters.cs`](https://github.com/jonklaric/XGoodFit/blob/fcb3902c2937662ed5f1b3869e0ea019e88e3c63/src/Framework/GenericControls/Utilities/Converters.cs#L224) and [`StringListPropertyControl.axaml.cs`](https://github.com/jonklaric/XGoodFit/blob/fcb3902c2937662ed5f1b3869e0ea019e88e3c63/src/Framework/GenericControls/Properties%20Controls/StringListPropertyControl.axaml.cs). Item 4's icons are `x:Shared="False"` in its [`IconDictionary.axaml`](https://github.com/jonklaric/XGoodFit/blob/fcb3902c2937662ed5f1b3869e0ea019e88e3c63/src/Framework/GenericControls/Resources/IconDictionary.axaml), because Avalonia throws where WPF moves the element.
